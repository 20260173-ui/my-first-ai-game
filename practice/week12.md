# 프로시저럴 생성 실습 정리

## 1. 오늘 가장 흥미로웠던 코드

세 코드 모두 흥미로웠지만, 그 중에서도 **펄린 노이즈 지형(perlin_terrain.py)** 과 **셀룰러 오토마타 동굴 생성(cellular_cave.py)** 이 특히 인상적이었다.

단순히 시각적으로 재미있어서만이 아니라, 현재 진행 중인 기말 프로젝트 게임에 실제로 활용 가능성이 보였기 때문이다. 기말 프로젝트는 메탈슬러그를 참고할 예정인데, 셀룰러 오토마타로 동굴 형태의 맵을 생성하고, 펄린 노이즈로 바닥 지형을 울퉁불퉁하게 만드는 방식을 조합하면 자동 생성 맵에 활용할 수 있을 것 같다는 아이디어가 떠올랐다.

---

## 2. 파라미터 변화 실험

### 2-1. `cellular_cave.py` — FILL_PROB (초기 벽 비율)

| 값 | 결과 |
|---|---|
| 0.3 이하 | 벽이 적어서 동굴이 넓고 탁 트인 느낌, 고립된 벽 조각이 많이 생김 |
| 0.4 (기본값) | 균형 잡힌 동굴 형태, 자연스러운 통로와 공간이 생성됨 |
| 0.55 이상 | 벽이 지나치게 많아 동굴이 거의 막히거나 아주 좁은 통로만 남음 |

초기 벽의 비율이 높을수록 최종 결과물도 답답하게 막히는 경향이 있었다. 반대로 너무 낮으면 동굴이라기보다 빈 공간에 돌덩이가 떠 있는 느낌이 되었다.

---

### 2-2. `cellular_cave.py` — ITERATIONS (반복 횟수)

| 값 | 결과 |
|---|---|
| 1~2회 | 아직 노이즈 상태에 가까움, 형태가 거의 잡히지 않음 |
| 5회 (원래 기본값) | 어느 정도 동굴 형태가 보이기 시작함 |
| 10회 (수정값) | 더 매끄럽고 안정적인 동굴 형태, 작은 고립 공간들이 흡수됨 |
| 15회 이상 | 거의 변화 없음, 일정 횟수 이후에는 수렴하여 더 이상 변화가 없음 |

반복 횟수가 늘어날수록 지형이 안정화되지만, 일정 횟수를 넘으면 변화가 거의 없어진다. 수렴(convergence)하는 특성이 있음을 확인했다.

---

### 2-3. `perlin_terrain.py` — OCTAVES (옥타브 수)

| 값 | 결과 |
|---|---|
| 1~2 | 매우 완만하고 단조로운 언덕, 세부 디테일 없음 |
| 4~6 | 부드러운 산과 계곡, 자연스러운 느낌 |
| 10 (기본값) | 큰 지형 위에 작은 굴곡이 겹쳐져 실제 지형에 가까운 느낌 |
| 15 이상 | 지형이 지나치게 울퉁불퉁해지고, 성능도 눈에 띄게 느려짐 |

옥타브는 노이즈를 여러 주파수로 겹치는 레이어 수이다. 낮으면 단순하고, 높으면 디테일해지지만 성능 비용이 올라간다.
다만 그렇다고 너무 높이 만드니 뾰족뾰족한 가시같은 지형이 생성되었다. 적당히 완만한 언덕같은 지형을 생성하려면 3정도의 산+언덕 느낌의 지형 생성이 좋을것같다.

## 3. 기말 프로젝트에서의 활용 가능성

기말 프로젝트에서 프로시저럴 생성을 활용할지는 **아직 미정**이다. 다만 실습을 통해 활용 가능성에 대한 아이디어가 생겼다.

### 떠오른 아이디어

기말 프로젝트는 메탈슬러그를 참고할 예정이다. 이 방식에 프로시저럴 생성을 접목한다면 다음과 같은 조합이 가능할 것 같다.

- **동굴 맵 구조** → `cellular_cave.py`의 셀룰러 오토마타로 동굴 형태의 맵 공간을 자동 생성
- **바닥 지형** → `perlin_terrain.py`의 펄린 노이즈로 울퉁불퉁한 지면을 자연스럽게 생성

두 방식을 조합하면 매번 다른 느낌의 스테이지를 자동으로 만들 수 있을 것 같다.

### 고려할 점

- 완전 랜덤 생성은 클리어 불가능한 맵이 나올 수 있어, **생성 후 유효성 검증(예: 시작점~목표 도달 가능 여부)** 로직이 추가로 필요하다.
- 횡스크롤 게임 특성상 진행 방향이 정해져 있으므로, 완전 자유로운 동굴 생성보다는 **좌→우 방향으로 통로가 이어지도록** 제약을 추가하는 방향을 고려해야 한다. 즉 오른쪽에는 초기 지형이 생성되지 않도록 만드는것이다.
